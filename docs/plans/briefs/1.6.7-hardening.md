## What the audit found (in order of importance)

### 1. One piece of writing that cannot be read stops all reading (pad)

`src/pad.js`, `_schedule` / `_warm` / `recognize` / `_readParts` / `_emit` have no error handling. If reading one
cluster of ink throws (an engine bug on some odd ink, a bad option, non-finite numbers), the exception escapes from a
timer, no result is ever emitted, and every later read throws again at the same cluster: the whole page stays unread
until that ink is erased, with nothing to tell the user. Proven two ways: a saved stroke with coordinates near 1e308
(`Cannot read properties of undefined (reading 'c')` in `Recognizer.segment`, on every read), and by making
`Nib.Recognizer.prototype.recognize` / `warmup` throw for one cluster (result stays null, 0 `nib:result` events).

Fix, with the principle "the optional intelligence must never break the basics" (writing, erasing, undo, saving):

- In `separate` mode (the Board): a cluster whose `warmup` or `recognize` throws is left as ink (an empty reading for
  that cluster), the other clusters are read as usual, and the bad cluster is not retried until its strokes, its
  corrections, the options or the memory change (i.e. its part key changes), so it costs nothing per read.
- In single-expression mode: a read that throws gives an empty result (as for no ink), not an uncaught error, and is
  not retried for the same ink.
- `_emit`: a failure while planning the views or working out answers (`_replan`, the solver, the training log) must
  not stop the result from being stored and announced; fall back to showing the ink as written for what failed.
- Painting: one element or one planned item that throws while being drawn must not blank the rest of the board;
  the canvas state (transform, save/restore depth) must be sound for what is drawn after it.
- Pen lift (`_finish`): a failure in scribble detection (`_scribbleOut`, `_scribbleJoin`) or hold-to-shape keeps the
  stroke as ink.
- Reporting: each distinct failure is said once with `console.warn('Nib: …', error)` (not once per frame or per
  read), kept in a small list on the pad (`pad.faults`, the last 20: `{where, message, time}`), and announced as a
  bubbling `nib:fault` CustomEvent on the element with `detail: {where, error}` (`where` one of `'read'`, `'plan'`,
  `'answers'`, `'paint'`, `'scribble'`, `'train'`). Document the event and `faults` in README.md beside the other
  events.
- Tests (browser): fault injection by wrapping `Nib.Recognizer.prototype.recognize` / `.warmup` for one cluster: the
  other two clusters are read and answered, `nib:result` fires, one warning and one `nib:fault`, no page error;
  writing a new stroke, erasing, undo and `getState`/`setState` still work; removing the bad ink brings a normal
  result. A reading whose result object is malformed (inject one: e.g. a symbol with `box: null`, `lines: undefined`)
  must not throw out of `_emit` or out of painting. Also the single-expression pad.

### 2. Non-finite numbers and null coordinates (engine and pad)

- `Recognizer.segment` (`src/recognize.js`): when the scores are NaN (seen with coordinates near 1e308, and with
  options `prior: ±1e9`, `wJunk: NaN`, `wClass: NaN`), no end state is chosen and it crashes. Make the segmentation
  total: non-finite scores must never leave it without a path (treat them as the worst score, or fall back to one
  symbol per stroke). `Nib.classify` must not return NaN probabilities either. Numeric options that are not finite
  numbers fall back to their defaults.
- `normStrokes` (`src/recognize.js`): `Nib.recognize(42)`, `('abc')`, `({})`, `(true)`, a function, a Date, an
  arguments-like object throw `(input || []).forEach is not a function`; `[[null, null]]` throws; `[{points:
  {points: []}}]` throws (`pts is not iterable`); BigInt points throw. The suite's own contract (`test/check.js`
  section 2) is "bad and odd input never throws". Anything that is not an array of strokes reads as nothing; a point
  that is not two finite numbers (or numeric strings, which are accepted today and stay accepted) is dropped. Note
  `+null`, `+''`, `+true`, `+[]` are 0 or 1: today a `null` coordinate (which is what `JSON.stringify` makes of NaN)
  becomes a point at 0, i.e. a spike to the origin. `null`, `''`, booleans, arrays and objects are not coordinates:
  drop the point. The same rule in the pad's `_cleanStrokes` and anywhere else points come in from outside
  (`setStrokes`, `setState`, `syncStrokes`, `addElement`, `handClean` in `src/neat.js`, `storePack`). The
  Replicator's `cleanStrokes` already does this; match it.
- Coordinates of absurd size: a point with |x| or |y| above 1e9 is not on any board (the camera clamp below keeps
  writing inside it). Drop such points wherever points come in, so the float math in the classifier and layout cannot
  overflow. `Nib.hand.load` with such glyphs gives NaN strokes in the hand view today: glyph points must be finite
  and of sane size (a glyph is drawn in a unit box; allow a generous margin).
- Tests (node): the cases above, plus "a null coordinate drops the point, it does not become 0".

### 3. The camera has no bounds (pad)

`_putView`, `setCamera`, `panBy`, `zoomAt` (`src/pad.js`) clamp the zoom but take any finite x and y. A saved camera
of `{x: 1e308, y: -1e308, z: 1e9}` opens the board in empty space; what is then written has coordinates that crash
the reader (item 2) and that are lost on save and reload (7 strokes written, 0 came back). Clamp the camera's x and y
to ±1e9 everywhere the camera is set or moved, and say so beside `PAD_ZMIN`. Test (browser): that saved camera opens
without error, writing there is read, saved and comes back after a reload.

### 4. A very long stroke freezes the Board when the pen lifts (scribble detection)

`scribbleOf` (`src/scribble.js`) runs on every pen and marker stroke at pen lift. Its cost is unbounded: `scrRepeats`
compares every leg with every earlier leg (quadratic in legs), `scrOverlap` walks the path every 0.75 screen px into
a Map keyed by strings (work and garbage proportional to the path's length in screen px). Measured in the Board:

| one stroke | pen-lift freeze, this machine | with the CPU slowed 4x |
| --- | --- | --- |
| 2,000 point zig-zag | 67 ms | 253 ms |
| 8,000 points | 766 ms | 2,980 ms |
| 16,000 points (a minute of shading) | 1,350 ms | 5,748 ms |
| 40,000 points | 3,764 ms | 15,878 ms |

The pad uses coalesced pointer events, so an S Pen gives about 240 points a second: 8,000 points is half a minute of
coloring in. Through the API (`Nib.scribble.of(points, z)`, used by Deckhand) with large coordinates and `z` left at
1 the same detector runs for minutes (a 73-point zig-zag scaled by 10,000: 41 s), and a 200,000-point stroke never
finishes.

Fix: give the detector a hard work bound, without changing any decision for a stroke a hand can make as a scribble.
A stroke beyond what a scribble can be is ink: more points than a scribble has, a path longer in screen px than any
scribble, more legs than a hand makes. Choose the bounds from the numbers (a real scribble-out is seconds long: a few
hundred to a few thousand points, a path of at most tens of thousands of screen px, well under a thousand legs) and
state them as named constants with their reasons. Target: pen lift under about 150 ms on this machine for ANY stroke
(so under about 600 ms at 4x), and `Nib.scribble.of` under 250 ms for any input whatever its size or scale. If you
also make `scrOverlap`'s grid cheaper (numeric keys), prove the results are identical to the old function over the
suite's corpus (a differential check in the test), or leave it alone.
`test/scribble_check.js` (its "real writing never rubs anything out" replay and its thirteen kinds of scribble) must
pass unchanged, with the same counts. Tests: timing bounds for the shapes in `/tmp/fuzz/scr_scale.js`,
`/tmp/fuzz/scr_legs.js` and the table above (node, and one in the browser: a 16,000-point pen stroke dispatched as
pointer events, the longest stuck frame after pen lift under a stated bound).

Also pin the rule the suite does not pin today (a mutation changing `SCR.share` and three other 0.6 thresholds to
0.4 passed `scribble_check`): add boundary cases for what a scribble takes: a neighbor stroke about half under the
scribble stays, one mostly under it goes, with the shares printed.

### 5. The Replicator hangs on a letter written far outside its box

`replicator/template.html`: a box's pointer handler keeps the pointer captured and stores box coordinates without
limit (`at` for boxes, and the sentence strip's `at`), so a stroke that starts in a box and slides across the screen
is kept with coordinates 10 to 25 boxes away. `replicator/core.js` `resample` and `rasterize` then do work quadratic
in the glyph's extent: with coordinates up to 10 boxes one outline takes 0.9 s, 30 boxes 7 s, 100 boxes 43 s or
`RangeError: Array buffer allocation failed`. The font is rebuilt after every change and at every load, from
localStorage, so the page stalls or hangs each time it is opened (my probe: every letter out of the box, the page
never answered again). Fix: a box's strokes are clipped to the box with a margin where they are captured (decide the
margin from how descenders and tall strokes are drawn today; it must not change any glyph written inside its box);
saved work and opened files are held to the same range (`adopt`); `outline`/`rasterize`/`resample` in the core
refuse or clip what is out of range instead of allocating or looping without bound, so `buildFont` returns in
bounded time for any input and never throws. `test/replicator_check.js`, `font_check.js` and
`replicator_browser.js` must pass unchanged. Tests: node (`buildFont` with out-of-range glyphs: time bound, valid
font, the bad glyphs skipped or clipped as you decide and say) and browser (the page opened with that saved state
stays alive; a stroke dragged far out of a box is clipped).

### 6. `<nib-pad symbols="...">` with an unknown name stops reading

`allowedMask` (`src/core.js`) throws `Nib: unknown symbol set x` for an unknown name: right for
`Nib.recognize(strokes, {symbols: 'typo'})` (a tested contract in `test/check.js`: keep it), but in a pad it is thrown
on every read from a timer and the pad never reads. In the pad (the attribute and `setOptions`), an unknown set falls
back to `'school'` with one console warning. Also `PRESETS[symbols]` is looked up without an own-property check, so
`symbols="__proto__"` / `"constructor"` / a number / an object reach `spec.exclude is not iterable`: look presets up
as own properties and give the same clear error for anything that is not a known name, an array of labels or
`{include}` / `{exclude}`. (Of 1,650 garbage attribute values over all 33 attributes, only `symbols` failed.)

### 7. Small guards (each a few lines; tests in `hardening_check.js`)

- `Nib.solve({tree: …})` with a malformed tree throws TypeErrors (`{tree: [[null]]}`, `{tree: {}}`, `{tree: 'x'}`,
  a `sup` that is a string, a label that is a number, a tree that contains itself: stack overflow). String input is
  already total (10,455 adversarial strings: no throw, no hang). A row that cannot be worked out for any reason is
  `null`; a `tree` that is not an array of rows is `[]`.
- `Nib.canvas.pdfFit(0, 0, 0, 0)` and non-numeric sizes give NaN: return finite numbers.
- `Nib.canvas.color(5)` / `({})` / `([])` return the value given: a color that is not a string is the ink color.
- `Nib.canvas.shapeFromDrag(kind, undefined, undefined)` throws: return null for points that are not points.
- `Nib.scribble.erase` / `.covers` given something that is not a scribble from `Nib.scribble.of` throw: return
  `{erase: [], why: 'not a scribble'}` / a zero cover.
- `board/board.js` `openBoardFile`: `f.text().then(...)` has no rejection handler; a file that cannot be read says
  so with a note, as a file that is not a board does.

### 8. Tests the mutation sample showed are missing (add to `hardening_check.js`)

I broke one thing at a time and ran the suite that should notice. Caught: storage precision, PDF xref, shape snap
angle, 1/0, the scribble leg count. NOT caught (add a direct check for each, as characterization of today's
behavior):

- solver limits: the factorial limit (`200! ÷ 199! =` gives 200, `201! ÷ 200! =` gives nothing), the power-of-
  letters limit (`x^{12}x^{12} =` gives `x^{24}`, `x^{13}x^{12} =` gives nothing), the size limit `SOLVE_BITS`
  (find the largest power of 2 that still answers in a quotient like `2^{n} ÷ 2^{n-1} =` and pin both sides), the
  root index limit (64 / 65), the repeating-decimal length limit (12 / 13 digits), the 24-digit answer limit
  (`2^{79}` / `2^{80}`).
- `+` written over `−` reads as `±` (`src/recognize.js` near "label = '\\pm'"): compose one from real strokes in
  `test/school_synth.jsonl` (a `+` above a `-`), and the neighbors `-` over `-` → `=` and two stacked dots → `:`.
- the memory cap (`MEM_MAX` = 400 corrections) and that a correction pulls only near-identical shapes (`MEM_SIM0`).
- the tidy view's exponent size (`NEAT.script` 0.65): a mutation to 0.5 passed `neat_check`.
(The pad and Board mutations were all caught by the browser suites: the undo cap, undo of an erase, the zoom limit,
the save delay. Nothing to add there.)
